## 1. Provenance & Consolidation Methodology

This document provides the definitive trace of all code, configuration, data splits, trained checkpoints, feature embeddings, FAISS galleries, and evaluation reports consolidated into `SENTINEL-RS` from four team members' repositories:

- **Person 1 (Jainam)**: `cross-modal-remote-sensing-retrieval` (Lead, Subset verification, 30k splits, baseline retrieval scripts, final Week 5 reports)
- **Person 2 (Adarsh)**: `deep-cross-final-yr-project` (Metadata exploration, S2 preprocessing, 21k stats, mAP engine, validation embeddings, t-SNE)
- **Person 3 (Meet)**: `majorProject` (SAR preprocessing, s1_stats, paired DataLoader, interactive Atlas Flask web portal, FAISS index galleries)
- **Person 4 (Fateh)**: `majorproject_week3` (Baseline extractor, Two-Tower architecture design, contrastive training loop, project log)

### Architectural Separation Principle
1. **Local PC Environment (`weeks/` & `results/local_pc/`)**: Contains the historical 30,000-patch local PC experimental pipeline, source scripts organized strictly by weekly milestones, and verified artifacts.
2. **PARAM SHAVAK Environment (`param_shavak/` & `param_shavak/results/`)**: Contains an identical directory structure skeleton kept segregated for Linux HPC cluster execution so cluster results never contaminate local PC benchmarks.
3. **Shared Artifacts (`shared/`)**: Centralized common assets including documentation, project roadmap, configuration specifications, utility modules, and the trained model checkpoint (`best_model-v1.ckpt`).
