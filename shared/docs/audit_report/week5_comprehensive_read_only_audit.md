### Section E: FAISS Implementation & Search Methodology
- **Index Architecture**: Both `sar_gallery.index` and `ms_gallery.index` are built using `faiss.IndexFlatIP(512)`.
- **Mathematical Equivalence**: For unit-norm vectors $u, v \in \mathbb{R}^{512}$ with $\|u\|_2 = \|v\|_2 = 1$:
  $$\langle u, v \rangle = \sum_{i=1}^{512} u_i v_i = \|u\|_2 \|v\|_2 \cos(\theta) = \cos(\theta)$$
  Inner product search on L2-normalized embeddings is mathematically identical to cosine similarity search.
- **Index Sizing**:
  $$\text{Data Size} = 4,500 \times 512 \times 4 \text{ bytes} = 9,216,000 \text{ bytes}$$
  $$\text{Header Overhead} = 45 \text{ bytes}$$
  $$\text{Total File Size} = 9,216,045 \text{ bytes}$$
  Both index files on disk match this size byte-for-byte.
- **Search Execution**: Queries are performed with `index.search(query_embedding, k)`. No vector compression, clustering (IVF), or quantization (PQ) is used; search is exhaustive and numerically exact.

### Section F: Retrieval Relevance & Metrics
- **Cross-Modal Retrieval (Exact Pairing)**:
  - Relevance criterion: Binary ground truth. A retrieved gallery patch $g$ is relevant to query $q$ if and only if $g = q$ (they originate from the identical geographic scene pair).
  - Metrics computed: Recall@1, Recall@5, Recall@10.
  - Formula:
    $$\text{Recall}@K = \frac{1}{N} \sum_{i=1}^N \mathbb{I}(\text{rank}(q_i) \le K)$$
  - Results:
    - SAR $\to$ MS: Recall@1 = 38.78%, Recall@5 = 64.82%, Recall@10 = 75.04%
    - MS $\to$ SAR: Recall@1 = 37.04%, Recall@5 = 63.73%, Recall@10 = 74.00%
  - Baseline comparison: Week 3 baseline cross-modal Recall@10 was 0.82% (SAR$\to$MS) and 2.13% (MS$\to$SAR). Two-Tower training achieved a **~91x improvement** in cross-modal retrieval.
  - Cross-modal mAP: Correctly omitted (reported as N/A). For single-positive retrieval, Average Precision@K is either $1/\text{rank}$ (if found in top $K$) or 0, which is Mean Reciprocal Rank (MRR) rather than conventional multi-label mAP.
- **Same-Modal Retrieval (Multi-Label Sharing)**:
  - Relevance criterion: Multi-label land-cover overlap. A gallery patch $g$ is relevant to query $q$ if:
    $$\mathcal{L}(g) \cap \mathcal{L}(q) \ne \emptyset$$
  - Self-exclusion: Crucial step. The query patch itself resides in the gallery and must be excluded. Verified in `evaluate_trained_same_modal_jainam.py` (lines 238–285): queries request $K+1 = 11$ neighbors, discard the entry where $\text{gallery\_idx} == \text{query\_idx}$, and retain the top 10 remaining candidates.
  - **Hit Rate @ K Metric Formulation** (Reconciled in Phase A.1):
    Code computes `if any(top_k_relevance): recall_counts[k] += 1`. This evaluates whether *at least one* relevant item is retrieved in top $K$, which is strictly **Hit Rate @ K ($\text{HR}@K$)**, not conventional multi-label Recall@K.
  - **Retrieved-Normalized AP @ 10 Metric Formulation** (Reconciled in Phase A.1):
    The implemented Average Precision formula normalizes by the count of relevant items *actually retrieved* in top 10:
    $$\text{AP}_{\text{ret}}@10 = \frac{1}{\sum_{k=1}^{10} \text{rel}(k)} \sum_{k=1}^{10} P@k \cdot \text{rel}(k)$$
    If no relevant items are in the top 10, $\text{AP} = 0.0$. This measures average precision among retrieved positives ($\text{AP}_{\text{ret}}@10$), rather than standard truncated AP@10 normalized by $\min(R_{\text{total}}, 10)$.
  - Results (Preserved Historical Values):
    - SAR $\to$ SAR: Hit Rate@1 = 53.40%, Hit Rate@5 = 85.98%, Hit Rate@10 = 92.49%, $\text{AP}_{\text{ret}}@10$ = 61.24%
    - MS $\to$ MS: Hit Rate@1 = 57.84%, Hit Rate@5 = 87.04%, Hit Rate@10 = 93.47%, $\text{AP}_{\text{ret}}@10$ = 64.09%

### Section I: Latency Benchmarking & Performance Reality
- **Critical Audit Finding**:
  In `weeks/week_05/benchmarking/timing_meet.py` (lines 239–274):
  ```python
  class PlaceholderEncoder(nn.Module):
      def __init__(self, in_features: int = 2, out_features: int = 64):
          super().__init__()

              nn.Flatten(),

Subsequent scripts (such as `generate_trained_tsne_meet.py`) process these unnormalized embeddings while claiming they are L2-normalized.

   `trained_test_sar_patch_ids.txt` contains S2 `patch_id` strings rather than S1 `s1_name` strings. This causes namespace inconsistency with the canonical dataset mapping and prevents direct lookup of raw SAR images by scene identifier.

   Multiple scripts contain hardcoded paths to previous developers' file systems (`C:\Users\hp\out\...`, `C:\BigEarthNet-S1-Required\...`), causing immediate `FileNotFoundError` unless executed on those specific machines.
